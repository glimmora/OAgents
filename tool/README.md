# Pipeline CI/CD OAgents

Pipeline ini berjalan di GitHub Actions tanpa build lokal: setiap push/PR ke `main` memicu `ci.yml` yang menjalankan gate murah dulu (dart format, flutter analyze, unit test terbagi 2 shard paralel dengan coverage), lalu membangun APK debug dengan `BUILD_NUMBER` dari nomor run. Job e2e mengunduh APK tersebut dan menjalankan `integration_test/app_e2e_test.dart` di emulator arm64 API 35 pada runner `ubuntu-24.04-arm` (APK hanya arm64-v8a) memakai bridge palsu via `--dart-define=E2E_FAKE_BRIDGE=true`, dan job ini non-blocking (warning di summary) karena boot emulator arm64 masih labil. Bila build gagal pada push ke main, job `autofix` menjalankan `dart format` + `dart fix --apply` lalu push commit bot `[autofix] ... [skip ci]` memakai `GITHUB_TOKEN` bawaan. Workflow `build-proot.yml` (manual/bulanan) membangun biner proot aarch64 dari ref terkunci di `env/env.lock` di runner arm64 dan mengunggahnya sebagai artefak yang dipakai CI utama untuk mengisi `android/app/libs/arm64-v8a/libproot.so` (placeholder kosong bila belum ada). Push tag `v*` memicu `release.yml` yang memverifikasi versi tag == pubspec, membangun APK per-ABI + AAB (signed bila secret `KEYSTORE_BASE64` ada, unsigned dengan catatan bila kosong), memverifikasi tanda tangan (apksigner, fallback keytool+jarsigner), lalu membuat GitHub Release dengan changelog `git log` sejak tag sebelumnya plus sha256sum semua artefak. Helper `scripts/ci_rootfs_cache.sh` mengunduh dan memverifikasi rootfs Alpine dari `env/env.lock` ke cache (untuk e2e rootfs asli di masa depan), dan Dependabot mingguan/bulanan menjaga versi GitHub Actions + Gradle tetap segar.
